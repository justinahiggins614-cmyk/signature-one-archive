1. What this Standard is

This document is the master version document for the Signature Spec Catalog record format. It declares one version — STANDARD v1.0, effective 2026-10-01 — and the record format every published spec carries is record version v1.0 (baseline). It describes existing practice; it changes no record data. It is published by Manon under his own patent authority — the JAH Signature-One Patent Authority — and is not a government standard, not USPTO-affiliated.

2. What the Standard governs

  • Record identity. Every specification carries a permanent deterministic ID — JAH-SPEC-###### for invention specs, JAH-WORD-###### for word inventions. IDs are never reused, never re-assigned, and never silently changed. Example published records: JAH-SPEC-325051 (first record in the main published index) and JAH-SPEC-426870 (most recent in the main published index at time of writing).
  • The forced Signature-One spec format. Title, abstract, six-tool signature mapping (line, triangle, square, cross, circle, curvature), key parameters, a machine-readable autoread block, and the five reversed-allowance algorithm steps — plus patent draft, manufacture, measurements, AI explainer, runnable program, and working demo lenses.
  • Canonical record JSON + SHA-256 content hash. Each spec page publishes its canonical record text and the hash computed over it; any consumer can recompute the hash and verify the record. The hash covers the record data, not the page HTML.
  • SIGNATURE-1 VALID. A data/specification status meaning the record passes Signature-One schema validation. It is not physical, prototype, or manufacturing validation.
  • Provenance and lineage. Every record's governance identity block shows spec type (original draft, Signature-line, variant, version edition, revision, product line, MIX hybrid), provenance assembled only from recorded fields, and lineage (signature line, line notes, mix/variant parents).
  • Record version + revision history. Every record carries Record version: v1.0 (baseline) and a Revision history row. Revisions are additive: a changed record would bump the record version; the ID stays the same and old versions are never silently overwritten. No revision history is invented — records published before this document show v1.0 with no recorded prior revisions.
  • The Official Standard Version (OSV) layer. The gold Official Standard lens on each spec page is a separate filing-ready legal-standard package; the original draft is unchanged and corrections live only in the OSV layer, marked "filing-ready draft — NOT filed, NOT a granted patent".
  • Cross-site identity. Each record links to its counterparts by deterministic ID — the JAH-N dossier (?dossier=JAH-SPEC-######), the catalog's own deep link (specs.html?spec=JAH-SPEC-######), and the word invention (?word=<word>). PC-system records (JAH-PC-########) live on the PC Depository; a spec links to a PC system only where a deterministic relationship exists in the data.
  • Filing-package downloads. Labeled, generated-on-click downloads (patent package zip, spec record JSON, Arduino sketch, programs) — generated from the record data at click time.
  • Status and disclaimers. Every record is marked DRAFT — ready to review and file; not a granted patent, not filed, not affiliated with the USPTO or any government agency.
Governance note. This Standard sits under Manon's own patent governance — the JAH Signature-One Patent Authority. Like Disney has its own money, this system has its own deterministic legal-ID coding: the JAH-SPEC ID, the official stamp, and the content hash ARE the protection and credibility. This is his own patent authority — not the USPTO, not a government system.

3. Version and revision policy

  • Master version (this document) changes only when the record format itself changes: v1.0 → v1.1 for additive clarifications, v2.0 for format-breaking changes. Every change is logged in the changelog below.
  • Record version on individual specs stays v1.0 (baseline) for all published records. A future record revision bumps the record version and appends to that record's revision history — history is recorded forward, never invented backward.
  • No backfill. Seed, generator, and revision information is stamped into new records forward-only; older records keep v1.0 with no fabricated history.
