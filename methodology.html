How the Catalog Is Built

The counting, identity, storage, and honesty rules underneath the Signature Spec Catalog — published so humans, search engines, and AI systems can read exactly what this archive is and how it grows.

1. The JAH-SPEC ID scheme

Every specification carries one permanent identifier of the form JAH-SPEC-###### — for example JAH-SPEC-000123. IDs are assigned sequentially from 000001, are never reused, and are stamped on the record itself, on every patent-figure sheet, and inside the record's canonical hash. A spec's permanent address is https://justinahiggins614-cmyk.github.io/signature-one-archive/specs.html?spec=JAH-SPEC-###### — a numeric ID alone (e.g. ?spec=123) resolves to the same record.

2. Drafts — not granted patents (honesty rule)

Every entry is a draft invention specification authored by Justin Addam Higgins (JAH) — original drafts, written in the forced Signature-One format, marked ready to review and file. Specs carrying a Signature-line badge (Signature AI, Signature Software, Signature Code, Signature Gaming, Signature Hardware) are JAH's original designs in the same product area as a public patent record — not the patented invention itself. The catalog never rewords or copies other people's patents.

3. Shard architecture

The archive is split for scale and speed:

  • 150-spec data chunks, lazy-loaded — the catalog page stays fast while the archive grows toward 1,000,000+ specs.
  • 26 frozen shard repos hold the oldest chunks (JAH-SPEC-000001 through JAH-SPEC-523050, 523,050 specs); the main repo holds the newest chunks and the search index. The file data/index/shards.json lists every shard in order — IDs are contiguous across shards with no gaps. (Auto-updated 2026-10-03.)
  • An 850 MB repo-size guard on the data directory: when a drip run would cross it, the oldest chunks move sideways into a new shard repo. Growth is always sideways — records are never cut or trimmed to make room.

4. Versioning

The record format is governed by The Spec Catalog Standard (STANDARD v1.0, effective 2026-10-01). Every published record carries a record version (v1.0 baseline) and a revision-history row on its identity block, so any later correction is traceable. The Official Standard Version (OSV) lens shows a filing-ready rendering of a record — the original draft underneath is never changed; corrections live only in the OSV layer.

5. What "SIGNATURE-1 VALID" means

SIGNATURE-1 VALID means the record's autoread block passes Signature-One schema validation — a data/specification status, not physical or manufacturing validation. It says the record is well-formed under JAH's own format; it makes no claim about whether the invention works, is buildable, or is patentable.

6. The "Era" filter

Era is the invention's time context as classified when the spec was generated: Past (a historical-style invention), Current (present-day), or Future (a projected, forward-looking concept). It is descriptive only — it is not a claim about when the invention was actually invented, filed, or built, and it carries no patent-status meaning.
